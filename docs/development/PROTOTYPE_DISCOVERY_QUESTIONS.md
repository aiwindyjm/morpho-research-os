# Prototype Discovery Questions

These questions are the decisions needed before the static prototype becomes a real product workflow. They are intentionally separate from the canonical PRD until the maintainer answers them.

1. What is the first research topic you want to complete end to end?
2. Should the first screen open to Projects, the last active project, or a New Research form?
3. What is the minimum information required before a plan can be generated?
4. Should a user be allowed to run a plan without editing or approving it?
5. Which default research dimensions should appear for a new project?
6. Should custom dimensions be free text, reusable presets, or both?
7. What does “research depth” mean to you in actual output volume and source count?
8. What source types must work in the first usable build: web pages, PDFs, papers, GitHub, official sites, or something else?
9. Which search providers are available to you, and which can be used without a paid API?
10. Should the user paste URLs manually in the first build?
11. What is the minimum source quality information you need to trust a result?
12. Which claims require mandatory evidence before they can enter the Vault?
13. Should unsupported extracted text be stored as a draft, rejected, or shown as unverified?
14. How should conflicting claims be shown to a user who is not a researcher?
15. What is the preferred unit of review: source, claim, knowledge node, task, or batch?
16. Should the generated Vault use English folder names, Chinese folder names, or configurable names?
17. How should Morpho behave when a user manually edits a generated Markdown note?
18. Should the first Vault be created inside a user-selected existing folder or in a new project folder?
19. What should “Open in Obsidian” do when Obsidian is not installed?
20. Which graph interactions are essential: search, filter, click inspector, neighborhood, or only overview?
21. What is the most useful progress signal: task count, source count, estimated time, or current action?
22. When a task fails, should the default action be retry, skip, change provider, or ask the user?
23. Which AI providers do you want available on the first settings screen?
24. Will you use local Ollama/GLM models, remote OpenAI-compatible APIs, or both?
25. Which model settings must be visible to you, and which should remain automatic?
26. Should daily AI conversation journals be Markdown only, JSON only, or both?
27. Should the journal include tool calls and file changes, or only human-readable messages?
28. Do you want one journal file per day per project, or one file for all Morpho development conversations?
29. How should a conversation decision be promoted into the public project docs?
30. What must never be retained locally in a conversation journal?
