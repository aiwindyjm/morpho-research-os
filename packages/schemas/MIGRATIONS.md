# V0.1 SQLite Migration Plan
`migrations/001_initial.sql` creates projects, research_configs, plans, sections, runs, tasks, task_dependencies, sources, source_contents, knowledge_nodes, claims, evidence, relations, artifacts, events, llm_usage, and schema_meta. All tables have UUIDv7 primary keys, created_at/updated_at where mutable, foreign keys, and indexes required by docs/DATA_MODEL.md. Future changes are new numbered files only.

- `002_task_skip_and_orchestrator.sql`: adds `SKIPPED` + `skip_reason` to tasks, `needs_review` to runs, and `task_dependencies.condition` (table rebuild).
- `003_plan_metadata_and_gap_decisions.sql`: plan metadata columns and the `gap_decisions` table.
- `004_run_worker_job_id.sql`: adds the nullable, indexed `runs.worker_job_id` — the persisted run → worker-job binding so `run_latest_get`/`run_cancel` survive restarts (ADR-024).
- `005_source_content_class.sql`: adds `source_contents.content_class` (`full-text` | `snippet` | `unavailable`) — the worker's content-availability classification, persisted so evidence locators stay auditable after worker exit (review R8). Existing rows backfill to `unavailable` by the verifiable fact that the pre-005 writer never persisted a body (`cache_path` was always empty); a `full-text` default would have claimed bodies that do not exist (round-2 review P2).
- `006_delivery_status_and_evidence_locator.sql`: adds `runs.delivery_status` (`pending` | `delivered` | `failed` | `unknown`) separating the execution projection from the RESULT-DELIVERY fact (round-2 review P1); backfills pre-migration terminal runs to `unknown` (never `delivered`); heals pre-005 content rows still claiming `full-text` with an empty cache path; and adds `evidence.locator_detail` for the lossless structured locator (JSON incl. the worker's original `retrieved_at`) next to the flattened display string.
