## Unreleased

Eleventh push — failure-convergence and honest-promises campaign over the 2026-09-18 PRD source audit — automated-suites-only, **NOT yet verified by the maintainer**:

- **Worker-death convergence while the core lives (audit A1)**: when the supervisor detects the worker process dying mid-run (previously: the job vanished from tracking while the run row stayed `running` forever), the event pump now converges every interrupted job's run durably — non-terminal runs close as `cancelled` through the same atomic event+projection transaction startup recovery uses (the auditable `run.cancelled` event is re-emitted to windows), and terminal-but-undelivered runs keep their execution fact while their `delivery_status` flips to durable `failed`. This is convergence, NOT checkpoint resumption (PRD §7 durable resume remains a pending decision). Interruption convergence retries when its own persistence fails, is idempotent (exactly one convergence event), covers two projects' jobs independently, and runs even when the restart budget is exhausted. `needs_review` runs stay parked, never auto-closed.
- **Post-commit delivery notification (audit A2)**: a successful delivery retry now notifies AFTER the domain commit — the pump re-emits the run's persisted terminal run event (existing vocabulary, existing log row; no new event types invented), and the frontend gains a bounded `DeliveryWatchBridge` that tracks result delivery through the existing `run.get` read API: while any project's run has a pending delivery it polls fast (900 ms), durable-failed deliveries keep a slow re-arm watch (5 s), run lifecycle events re-arm the watch, and polling stops entirely when nothing is in flight — discovery never depends on manual refresh, view switches, or window focus. The watch also feeds every project's run into the canonical run cache, so event attribution follows the OWNING project: a background project A run no longer refreshes project B's caches while B is active, and A's domain caches invalidate the moment its delivery lands (first-observation snapshots never count as transitions, so mounting the app on already-delivered runs causes no invalidation storm).
- **Gap-approval executability (audit A3)**: approving a gap proposal against a plan that could never execute it (already executed, or mid-run) now refuses with an accurate, actionable reason and persists NOTHING — no follow-up task, no `approved` decision; the gap stays proposed. `plan_regenerate` carries UNEXECUTED approved gap follow-ups into the new draft (fresh task identity, decision re-linked), so a user-accepted follow-up survives regeneration instead of silently orphaning; executed follow-ups stay historical, and a still-gapping dimension may accept a new round after its earlier follow-up executed. The natural path (first run completes → regenerate → re-approve → run) executes end to end; the Overview card surfaces the core's refusal reason instead of failing silently. The follow-up remains a single search task (the approved V0.1 PRD §14 shape); the full gap-driven chain stays a §17/decision-package item.
- **Cache rollback compensation no longer deletes committed references (audit A5)**: a batch that repairs/recreates a content-addressed cache file a committed `source_contents` row references, then fails later, keeps the repaired file — the content-addressed name guarantees the bytes match the committed fingerprint, so the reference stays usable instead of dangling. Only files no persisted row references are compensation-deleted. New targeted regressions: repair-then-rollback, missing-file-recreation-then-rollback, and an unpublishable target (Windows rename/replace failure) rejecting the batch with no temp litter.
- **Honest default execution mode (audit A4)**: a clean config (no `app.json`) now defaults `worker.transport` to `"http"` — the real Python worker launcher — so a missing runtime surfaces at run start as the structured, actionable, non-retryable `WORKER_NOT_AVAILABLE` (the spawn error names the fix; no ghost run; the approved plan stays reusable) instead of the no-op fake silently "succeeding". The hermetic fake remains available as an EXPLICIT demo choice. The parent-death shutdown contract is now verified mid-run on a real process (stdin EOF → graceful exit 0, worker pytest).
- Verified by: cargo 294 workspace (incl. the converted audit counterexamples as regressions: worker-death convergence ×7, delivery-retry notification, spent/running-plan gap refusals, regenerate carry-over, cache compensation ×3, clean-config default, production-factory run start), `cargo fmt --check` + workspace `clippy -D warnings` clean, worker pytest 265 (incl. mid-run stdin-EOF), schema pytest 68, vitest 275+59+132 (desktop/ui/schemas), typecheck clean, the four gates, Vite build, Playwright 11/11, and the real-process smoke re-run (8/8 tasks, restart readback, recovery, regenerated run) — **no human testing performed; checkpoint resume, real search/content fetching, cross-round increments, and installer verification remain open (consolidated decision package delivered separately); ADR-014/020/024/025 remain Proposed**.

Tenth push — correctness campaign over the 2026-09-17 round-2 review (four P1s + two P2s) — automated-suites-only, **NOT yet verified by the maintainer**:

- **Durable result-delivery state (round-2 P1)**: migration 006 adds `runs.delivery_status` (`pending`/`delivered`/`failed`/`unknown`) — execution terminal and result-delivery terminal are now separate persistent facts. `delivered` commits inside the ingestion transaction; exhausted automatic retries (8) park durably as `failed` and re-arm with backoff (8-cycle cool-down) while the job lives, so a healed failure recovers WITHOUT a new terminal event or a restart; startup recovery converges undeliverable runs (worker died with the core) to `failed` with an auditable `run.result_delivery_failed` event, and legacy terminal runs backfill to `unknown`, never `delivered`. The read model (`run_latest_get`, `run_get` rollup) exposes `delivery_status`, and the Tasks run badge renders 结果交付中/结果未交付 (10 locales) instead of full completion while results are undelivered — the real `run.completed → job.completed → ingest` order can no longer present an undelivered run as fully done. Reviewer's 8-failure injection now recovers (regression `exhausted_delivery_recovers_and_never_claims_full_completion`); validation-failure and crash-after-terminal scenarios regress-tested.
- **Provable cache ↔ SQLite consistency (round-2 P1)**: every `source-content` payload is SHA-256-verified against its declared fingerprint (the worker's `content_fingerprint`), lands through a unique hidden temp file + atomic rename, a referenced file whose bytes no longer hash to its name self-heals on re-ingest, and a rolled-back batch compensates by removing the files it created — the reviewer's tampered-payload rollback reproduction now rejects at the fingerprint check and committed payloads are never mutated (`a_rolled_back_batch_never_mutates_committed_cache_content`, `a_corrupted_cache_file_self_heals_on_reingest`).
- **Desktop provider routing (round-2 P1)**: the handoff now emits `MORPHO_ROLE_*` for all five LLM roles when exactly ONE provider is configured (unambiguous), refuses multi-provider configurations loudly (naming ADR-025) instead of silently picking the first, and leaves the embedding role on the worker default (LLM-only model). Worker-side FINAL selection is asserted in Python (`tests/test_desktop_handoff_selection.py`: `from_env` + `ProviderFactory` resolve the desktop provider for every role; explicit `kind=search` selects SearXNG; routed-but-missing fails at config validation). The full kind/protocol/role config model is PROPOSED as ADR-025 (decision material only — not implemented, not self-approved).
- **Atomic core-originated events (round-2 P1)**: `run_cancel`'s worker-gone fallback now goes through the same atomic event+projection service as the pump and startup recovery (`recovery::converge_cancelled_run`: event + projection + delivery-failed fact in ONE transaction). A projection failure rolls the event back and the command returns an error — never a silent `true` (regression `run_cancel_convergence_is_atomic_and_reports_projection_failures` with an injected SQL trigger). No non-atomic core-originated state-event path remains.
- **Migration 005 backfill fix (round-2 P2)**: pre-005 content rows (whose writer always left `cache_path` empty — no body ever persisted) backfill to `unavailable`, never `full-text`; migration 006 carries a corrective UPDATE healing databases that applied the earlier draft default; a real v4→v5→v6 DATA migration test covers both backfills plus the runs delivery backfill.
- **Lossless evidence locators + original retrieval time (round-2 P2)**: migration 006 adds `evidence.locator_detail` (the structured locator as JSON: quote/section/url_fragment/position/retrieved_at); `evidence.retrieved_at` now carries the WORKER's retrieval time (locator timestamp, falling back to the source's persisted fetch time; `0` = unknown) — never the ingestion clock (regression `evidence_locator_detail_and_retrieved_at_persist_worker_facts`).
- Verified by: cargo 271+2+1+3 (incl. new migration and delivery/cache/cancel regressions), `cargo fmt --check` + workspace `clippy -D warnings` clean, worker pytest 264 (incl. 4 new handoff-selection tests), schema pytest 68, vitest + typecheck clean (delivery badge + 10-locale keys with parity), the four gates, Vite build, Playwright, and the real-process smoke re-run — **no human testing performed; ADR-024/025 remain Proposed; kind/protocol/role config, a frozen results-envelope schema, and real-provider/keychain/network verification remain open**.

Ninth push — correctness campaign over the 2026-09-16 closeout review (R1–R8): project-isolated ingestion identity, delivery-before-retire, atomic event+projection, plan-reuse refusal, startup recovery — automated-suites-only, **NOT yet verified by the maintainer**:

- **Project-scoped domain identity (review R1)**: worker-minted ids are deterministic per (type, canonical name) with no project dimension; the core now stores knowledge nodes, relations, claims, and evidence under project-scoped primary keys `<project_id>:<worker_id>` (nodes keep the worker id as their per-project slug), so two projects can research the same concept without `UNIQUE` collisions or cross-project mutations. Repository inserts/updates verify project ownership (a foreign project's batch carrying the same worker claim id is a structured error, never an update). Cross-batch references resolve through batch sets and per-project slug/claim lookups; pre-scoping databases keep working (legacy same-project rows are reused, not duplicated). Idempotency, cross-project isolation, atomic rollback, and reference traceability are unit-tested with the reviewer's own scenarios.
- **First-ingestion review states (review R7)**: `claims` inserts honor the worker's validated review lifecycle from the FIRST record (`needs_review`/`confirmed`/`superseded` no longer flatten to `draft`); status and confidence vocabularies are enforced at insert and update.
- **Delivery before retire (review R2)**: a terminal job event now marks the job results-pending; the pump fetches AND ingests before retiring, retries delivery on its own schedule (never depending on the terminal event arriving again), bounds the attempts, and parks delivery-failed jobs as observable instead of dropping them. Fetch, SQL-write, and ingestion failures each have regression tests; the reviewer's injected-trigger scenario now recovers and lands the source rows on the next cycle without duplicate facts.
- **Atomic event+projection (review R5)**: the pump persists each canonical event AND projects it in ONE write transaction — a failed projection rolls the event back with it, so the acknowledged cursor never advances past a projection that did not land. Bounded projection retries park the job (stalled, observable) instead of hot-looping; the empty logging function was replaced with real stderr logging.
- **Lock discipline (review R3)**: `run_start` and the pump never hold the supervisor and database mutexes together (including every error-cleanup branch); a timeout-guarded concurrency test churns pump cycles against concurrent run starts.
- **Plan-reuse refusal (review R4)**: a plan whose tasks were claimed by a run is spent — `run_start` refuses a fresh run of the SAME plan with the legal path named (`plan_regenerate` → approve → run) instead of returning a zero-task "success"; the refusal holds after completed, cancelled, and failed runs, old history is never rewritten, and unclaimed-task plans (a run that never started) may still run. Per-execution task instances (same plan, independent runs) need a schema decision and are listed as a pending item — not implemented, not self-approved.
- **Results-envelope validation (review R6)**: ingestion verifies the schema version (`"1"` only), the envelope's job id against the drained job, and the run↔job↔project binding (migration 004); `records` is required; closed vocabularies (node/claim/confidence/direction/content-class enums) and evidence locator anchors are enforced; unresolvable references reject the whole batch instead of being silently skipped. The draft-wire deltas versus the frozen `worker-*.v1.json` gates are now itemized in `docs/api/WORKER_PROTOCOL.md`; ADR-024 remains Proposed.
- **Source-content persistence (review R8)**: content payloads land in core-owned cache files (`<app-data>/cache/source-contents`, filename-whitelisted, never inside the user's Markdown vault) with the availability classification (`full-text`/`snippet`/`unavailable`, migration 005 `source_contents.content_class`), fingerprint, and fetch time persisted; `unavailable` rows persist their class without a file. Cache read-back is tested.
- **Startup recovery (review E)**: `recovery::converge_interrupted_runs` runs at app start and closes every `running`/`paused` run left by a dead worker with an auditable core-originated `run.cancelled` event (the worker is a child process and dies with the core); `needs_review` runs stay parked for local review resolution; completed runs are untouched. Four interruption scenarios are unit-tested (mid-execution, terminal-but-undelivered, paused-from-failed-cycle, reopen-after-complete), and the real-process smoke now crashes a live run, reopens, converges, refuses the spent plan, and completes a regenerated one.
- **Execution semantics of edited descriptions (review E)**: the search query IS the approved task description — user edits steer execution verbatim (ADR-024's "what you approved is exactly what executes"); the scripted planner's search-task descriptions now carry the topic+dimension so defaults stay meaningful.
- **Desktop provider → worker handoff (review F)**: `worker_provider_env` builds the worker's `MORPHO_PROVIDER_*` environment from the desktop's Settings provider list with key values resolved from the secret store at spawn time (FakeKeychain-tested: handoff, missing-key auth error, no-mock-fallback, empty-handoff default); the HTTP transport injects it per spawn. Role routing from desktop Settings, real keychain values, and real network remain open.
- Verified by: cargo 261+2+1 (desktop incl. migration parity and the new regression suite), `cargo fmt --check` + workspace `clippy -D warnings` clean; worker pytest, schema pytest, vitest, typecheck, contract/architecture/boundary gates, desktop build, and the real-python-process smoke re-run below in the delivery report — **no human testing performed; ADR-024/020 remain Proposed and the per-execution task-instance schema, results-envelope JSON Schema, role routing, and real-provider/installer verification remain open**.

Eighth push — V0.1 research-loop closeout (approval→execution identity, result persistence, restart-safe reads) — automated-suites-only, **NOT yet verified by the maintainer**:

- **Approval & execution consistency (ADR-024, Proposed; audit F1)**: `run_start` now refuses plans whose persisted status is not `approved` (draft/rejected/superseded) and refuses a second active run per plan; a failed job submission cleans up the run row instead of leaving a fake RUNNING. The job envelope gains the optional `plan` member carrying the approved task tree — sections, core task ids, user-edited titles/descriptions, dependency edges — and the worker executes exactly that DAG verbatim (no re-planning, no worker-side self-approval). New worker runtimes `source_evaluation` (content + quality + LLM extraction per section, inline) and `normalization` (entities + relations + claims/evidence in one task); the core's scripted planner now emits real dependency edges (search → source_evaluation → normalization; validation waits for every normalization; synthesis waits for validation).
- **Result persistence (audit F2)**: new worker endpoint `GET /jobs/{id}/results` returns every validated record the job's sink collected; the Rust pump drains it once per terminal job, re-validates each record through strict serde structs (unknown fields rejected), and writes the traceability chain source → source-content → node → relation → claim → evidence (+ claim_evidence) in one transaction. Identity rules: sources upsert by canonical URL, nodes keep worker ids as id and slug (relation FKs resolve verbatim), claims/evidence keep worker ids (re-ingest is a no-op). **The real-process smoke now proves the loop end to end**: 8/8 approved core tasks advance to COMPLETED through their own events, an empty database gains 2 sources / 4 nodes / 4 claims / 4 evidence / 3 relations, coverage 0.65, the Vault exports 11 notes (map + sources + claims + knowledge), re-export is a no-op, and a fresh core over the same SQLite file reads back the run, rollup, frozen config snapshot, and graph.
- **Restart-safe reads (audit F4)**: migration 004 adds `runs.worker_job_id`; three new IPC commands (ADR-020 batch 3, Proposed alongside batch 2): `run_latest_get` (persisted run + task rollup + the FROZEN config snapshot of the executed plan — immune to later config edits), `plan_latest_view` (persisted sectioned plan projection), `gap_report_get` (decision-merged gap report). The frontend transport's session maps (jobs/plans/gap decisions) are deleted — run.get/run.cancel/plan.get/gap.list now read SQLite through these commands; run.cancel resolves the job through the persisted binding and, when the worker no longer knows the job (post-restart), converges locally via a `run.cancelled` projection through the ADR-019 state machine.
- **Event acknowledgment semantics (audit F5)**: the pump fetches without advancing its cursor, persists each event, and only then acknowledges through that sequence — a transient database failure replays from the worker instead of silently skipping, and unpersisted events are never emitted. Cancelling a job keeps it pollable until its terminal event has been persisted; results are drained and the job retired at exactly that point.
- **Provider configuration boundary (audit F3)**: `serve.py` no longer hardcodes mocks — it routes through `config.from_env` + `ProviderFactory` (an unconfigured environment stays offline by safe default; explicit `MORPHO_PROFILE`/`MORPHO_PROVIDER_*`/`MORPHO_ROLE_*` configuration is honored verbatim, and a configured provider failure surfaces structurally, never a silent mock fallback). `SourceContentResolver` now marks provenance (`full-text` / `snippet` / `unavailable`) so a search summary is never presented as a source's full text.
- **Honest task controls (audit F6)**: per-task pause/resume/retry/cancel stay visible in the Tasks view but are explicitly disabled with a "V0.1 暂不支持" marker and explanation (per-task dispatch is ADR-019 phase 2); run-start failures now surface their error message (e.g. the approval gate) instead of being swallowed. Ten-locale i18n keys added with structural parity guarded.
- **Gates**: the architecture-check conflict is fixed by moving the CSS value-pinning test out of `apps/desktop/src` (detector strength unchanged); all workspace clippy lints cleared; the PlanPage intermittent waitFor timeout widened with the observed evidence documented.
- Verified by: cargo 229+6 (desktop incl. migration parity, schemas), worker pytest 260, schema pytest 68, vitest 266+59+132 (desktop/ui/schemas), `pnpm -r run typecheck` clean, `cargo fmt --check` + workspace `clippy -D warnings` clean, contract/architecture/boundary/task-status/self-test gates green, desktop Vite build green, and the real-python-process smoke (run twice) — **no human testing performed; ADR-024 awaits maintainer ratification and the per-task dispatch (phase 2), real-provider runs, and installer verification remain open**.
