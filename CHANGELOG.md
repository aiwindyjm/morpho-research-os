## Unreleased

Eighth push — V0.1 research-loop closeout (approval→execution identity, result persistence, restart-safe reads) — automated-suites-only, **NOT yet verified by the maintainer**:

- **Approval & execution consistency (ADR-024, Proposed; audit F1)**: `run_start` now refuses plans whose persisted status is not `approved` (draft/rejected/superseded) and refuses a second active run per plan; a failed job submission cleans up the run row instead of leaving a fake RUNNING. The job envelope gains the optional `plan` member carrying the approved task tree — sections, core task ids, user-edited titles/descriptions, dependency edges — and the worker executes exactly that DAG verbatim (no re-planning, no worker-side self-approval). New worker runtimes `source_evaluation` (content + quality + LLM extraction per section, inline) and `normalization` (entities + relations + claims/evidence in one task); the core's scripted planner now emits real dependency edges (search → source_evaluation → normalization; validation waits for every normalization; synthesis waits for validation).
- **Result persistence (audit F2)**: new worker endpoint `GET /jobs/{id}/results` returns every validated record the job's sink collected; the Rust pump drains it once per terminal job, re-validates each record through strict serde structs (unknown fields rejected), and writes the traceability chain source → source-content → node → relation → claim → evidence (+ claim_evidence) in one transaction. Identity rules: sources upsert by canonical URL, nodes keep worker ids as id and slug (relation FKs resolve verbatim), claims/evidence keep worker ids (re-ingest is a no-op). **The real-process smoke now proves the loop end to end**: 8/8 approved core tasks advance to COMPLETED through their own events, an empty database gains 2 sources / 4 nodes / 4 claims / 4 evidence / 3 relations, coverage 0.65, the Vault exports 11 notes (map + sources + claims + knowledge), re-export is a no-op, and a fresh core over the same SQLite file reads back the run, rollup, frozen config snapshot, and graph.
- **Restart-safe reads (audit F4)**: migration 004 adds `runs.worker_job_id`; three new IPC commands (ADR-020 batch 3, Proposed alongside batch 2): `run_latest_get` (persisted run + task rollup + the FROZEN config snapshot of the executed plan — immune to later config edits), `plan_latest_view` (persisted sectioned plan projection), `gap_report_get` (decision-merged gap report). The frontend transport's session maps (jobs/plans/gap decisions) are deleted — run.get/run.cancel/plan.get/gap.list now read SQLite through these commands; run.cancel resolves the job through the persisted binding and, when the worker no longer knows the job (post-restart), converges locally via a `run.cancelled` projection through the ADR-019 state machine.
- **Event acknowledgment semantics (audit F5)**: the pump fetches without advancing its cursor, persists each event, and only then acknowledges through that sequence — a transient database failure replays from the worker instead of silently skipping, and unpersisted events are never emitted. Cancelling a job keeps it pollable until its terminal event has been persisted; results are drained and the job retired at exactly that point.
- **Provider configuration boundary (audit F3)**: `serve.py` no longer hardcodes mocks — it routes through `config.from_env` + `ProviderFactory` (an unconfigured environment stays offline by safe default; explicit `MORPHO_PROFILE`/`MORPHO_PROVIDER_*`/`MORPHO_ROLE_*` configuration is honored verbatim, and a configured provider failure surfaces structurally, never a silent mock fallback). `SourceContentResolver` now marks provenance (`full-text` / `snippet` / `unavailable`) so a search summary is never presented as a source's full text.
- **Honest task controls (audit F6)**: per-task pause/resume/retry/cancel stay visible in the Tasks view but are explicitly disabled with a "V0.1 暂不支持" marker and explanation (per-task dispatch is ADR-019 phase 2); run-start failures now surface their error message (e.g. the approval gate) instead of being swallowed. Ten-locale i18n keys added with structural parity guarded.
- **Gates**: the architecture-check conflict is fixed by moving the CSS value-pinning test out of `apps/desktop/src` (detector strength unchanged); all workspace clippy lints cleared; the PlanPage intermittent waitFor timeout widened with the observed evidence documented.
- Verified by: cargo 229+6 (desktop incl. migration parity, schemas), worker pytest 260, schema pytest 68, vitest 266+59+132 (desktop/ui/schemas), `pnpm -r run typecheck` clean, `cargo fmt --check` + workspace `clippy -D warnings` clean, contract/architecture/boundary/task-status/self-test gates green, desktop Vite build green, and the real-python-process smoke (run twice) — **no human testing performed; ADR-024 awaits maintainer ratification and the per-task dispatch (phase 2), real-provider runs, and installer verification remain open**.
